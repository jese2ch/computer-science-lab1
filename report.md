1. Описание системы

1.1. Назначение системы

Яндекс Карты — это цифровой картографический сервис, предназначенный для работы с картографической информацией. С помощью сервиса пользователь может просматривать карту, искать организации и различные объекты, получать информацию об организациях, определять местоположение и строить маршруты.

Сервис работает через веб-браузер и использует клиентскую и серверную части. Клиентская часть отвечает за отображение интерфейса и обработку действий пользователя в браузере. Серверная часть обрабатывает запросы, предоставляет данные и выполняет различные операции, необходимые для работы сервиса.

1.2. Целевая аудитория

Основными пользователями Яндекс Карт являются люди, которым необходимо:

найти определённую организацию или объект;
узнать адрес и расположение объекта;
посмотреть информацию об организации;
определить расстояние между объектами;
построить маршрут;
выбрать способ передвижения;
получить информацию о дорожной ситуации.

1.3. Основные возможности

К основным возможностям Яндекс Карт относятся:

просмотр интерактивной карты;
поиск организаций и объектов;
просмотр карточек организаций;
построение маршрутов;
выбор способа передвижения;
просмотр информации о дорогах;
отображение общественного транспорта;
просмотр отзывов и фотографий организаций;
определение местоположения пользователя;
работа с сохранёнными объектами и маршрутами.

1.4. Выбранный пользовательский сценарий

Для анализа был выбран сценарий:

«Поиск организации и построение маршрута».

В рамках сценария пользователь:

1. открывает Яндекс Карты;
2. вводит название организации в поисковую строку;
3. выбирает нужную организацию;
4. открывает карточку организации;
5. нажимает кнопку «Маршрут»;
6. указывает начальную точку;
7. выбирает подходящий вариант маршрута;
8. получает построенный маршрут на карте.

Таким образом, выбранный сценарий позволяет проследить взаимодействие пользователя с интерфейсом, клиентской частью, сетевыми запросами и серверными компонентами системы.

4. Анализ серверной части и API

Серверная часть информационной системы выполняет операции, которые не выполняются непосредственно в интерфейсе браузера.

Пользователь не видит внутреннюю реализацию серверов Яндекс Карт, однако о работе серверной части можно судить по сетевым запросам, ответам серверов и доступной документации API.

4.1. Сервер поиска

При поиске организации пользователь вводит поисковый запрос в интерфейсе.

Клиентская часть передаёт необходимые данные серверной части. Сервер обрабатывает запрос и возвращает результаты поиска.

Результаты затем передаются клиентской части и отображаются пользователю.

Упрощённо процесс выглядит следующим образом:

Пользователь
     ↓
Поисковая строка
     ↓
Клиентская часть
     ↓
Сервер поиска
     ↓
Данные организаций
     ↓
Клиентская часть
     ↓
Результаты поиска

4.2. Сервер маршрутизации

После выбора организации пользователь нажимает кнопку «Маршрут».

Клиентская часть передаёт серверной части данные, необходимые для построения маршрута.

В зависимости от выбранного способа передвижения и других параметров сервер рассчитывает подходящий маршрут и возвращает результат.

Упрощённо:

Начальная точка
       +
Конечная точка
       ↓
Клиентская часть
       ↓
Сервер маршрутизации
       ↓
Расчёт маршрута
       ↓
Результат
       ↓
Клиентская часть
       ↓
Отображение маршрута на карте

4.3. API

API можно представить как посредника между клиентской и серверной частями системы.

Клиентская часть отправляет запрос через соответствующий программный интерфейс, а сервер возвращает данные в ответ.

В рассматриваемом сценарии API может использоваться для:

поиска организации;
получения информации об объекте;
построения маршрута;
получения необходимых картографических данных.

Яндекс предоставляет официальные API для работы с картографическими данными и маршрутами.

4.4. Данные, участвующие в сценарии

При выполнении сценария могут использоваться следующие данные:

текст поискового запроса;
название организации;
адрес организации;
координаты объекта;
координаты начальной точки;
выбранный способ передвижения;
параметры маршрута;
данные о дорогах;
данные картографической системы.

| Компонент               | Назначение                                                                               |
| ----------------------- | ---------------------------------------------------------------------------------------- |
| Сервер поиска           | Обрабатывает поисковые запросы и возвращает найденные организации                        |
| Сервер маршрутизации    | Рассчитывает маршрут между заданными точками                                             |
| Картографический сервер | Предоставляет данные, необходимые для отображения карты                                  |

Внутреннее устройство серверов и конкретные базы данных Яндекс Карт недоступны для непосредственного просмотра через браузер. Поэтому информация о внутренних хранилищах является архитектурным предположением, основанным на функциях, которые должен выполнять сервис.


5. Описание пользовательского сценария

Рассмотрим полный сценарий поиска организации и построения маршрута.

Этап 1. Открытие сервиса

Пользователь открывает Яндекс Карты в браузере.

Браузер загружает необходимые HTML-, CSS-, JavaScript- и другие ресурсы.

Этап 2. Поиск организации

Пользователь вводит название организации в поисковую строку.

Интерфейс принимает введённый текст.

Клиентская часть обрабатывает действие пользователя и формирует запрос для получения результатов поиска.

Этап 3. Получение результатов

Запрос передаётся серверной части.

Сервер выполняет поиск по доступным данным и возвращает подходящие результаты.

Клиентская часть получает ответ и отображает найденные организации пользователю.

Этап 4. Выбор организации

Пользователь выбирает нужную организацию.

Открывается карточка организации с информацией об объекте.

Этап 5. Нажатие кнопки «Маршрут»

Пользователь нажимает кнопку «Маршрут».

Клиентская часть обрабатывает нажатие и открывает интерфейс построения маршрута.

Этап 6. Указание начальной точки

Пользователь указывает точку, откуда необходимо начать движение.

Конечной точкой является выбранная организация.

Этап 7. Построение маршрута

Клиентская часть передаёт серверной части необходимые данные.

Сервер маршрутизации выполняет расчёт маршрута и возвращает результат.

Этап 8. Отображение результата

Полученные данные передаются обратно клиентской части.

Клиентская часть обрабатывает ответ и отображает маршрут на карте.

Таким образом, пользователь видит готовый маршрут и может выбрать подходящий вариант.

В разделе Network были исследованы сетевые запросы, возникающие во время выполнения пользовательского сценария. Это позволило увидеть взаимодействие браузера с серверной частью системы.

Также были выделены предполагаемые серверные компоненты: сервер поиска, сервер маршрутизации, картографические компоненты и хранилища данных.

В результате было установлено, что даже простое действие пользователя — поиск организации и построение маршрута — требует взаимодействия нескольких частей информационной системы. Пользователь взаимодействует с интерфейсом, клиентская часть обрабатывает действия и отправляет запросы, серверные компоненты выполняют необходимые операции, после чего результат возвращается в браузер и отображается пользователю.

Таким образом, Яндекс Карты являются сложной информационной системой, состоящей из взаимосвязанных клиентских, серверных, API- и информационных компонентов.
